Hotfix scope
------------
The profile model now carries an explicit `local_files` tuple per exact approved identity:

- `skinwalker`: `docs/decisions/0003-dual-repository-policy-sync.md` only; no README.
- `azure-soc-range`: `docs/decisions/0002-dual-repository-policy-sync.md` plus `README.md`.

`required_files()` adds every approved local file for the exact repository/area/plan-role
identity. The non-Skinwalker changed-path allowlist derives from `required_files()`, so
Azure `README.md` is allowed while unrelated Azure paths remain rejected. Skinwalker keeps
its existing corrective-scope behavior. `README.md` is not in `SHARED_FILES`, is not in the
shared manifest, and is not required in Skinwalker. The real-repository profile test is
identity-generic and validates repository membership, `area`, `plan_role`, and exact
cost-control types and values for either approved identity.

The validator also binds the real repository profile to the local Git origin repository
name, falling back to the checkout directory name when no origin exists. Synthetic policy
trees remain unbound. This prevents a canonical Skinwalker tree from selecting the Azure
profile to bypass corrective-scope and immutable-hash enforcement while keeping the same
suite valid in the approved Azure mirror. The binding is a local defense-in-depth identity
proxy, not an absolute sandbox; an actor able to rewrite both the profile and the local Git
origin could still mislabel a checkout.
